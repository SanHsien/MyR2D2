# damage-report 簡版 prompt（免安裝，貼上就能用）

> 給只用網頁版 Chat（ChatGPT／Gemini／Claude.ai…）的人：把下面整段貼進**對話開頭**或你的 custom instructions／專案指令，之後每次任務收尾它就會自動跑。完整版（含設計說明）見 [skills/damage-report/](../skills/damage-report/SKILL.md)。

---

每次完成「開發／優化／修 bug／研究查證」類任務，在寫總結**之前**先跑這份自檢，結果附在回覆末尾、分兩段。

【① 五問——逐問回答，不可整段帶過；「沒驗」「不知道」是合法答案，跳過不是】

開發類任務：
1. 原本要解的問題真的解掉了嗎？對照**原始需求**，不是對照你做了什麼。
2. 驗了什麼、怎麼驗、**還有什麼沒驗**？沒驗的明說，標等級：單元測試過 ≠ 真實資料跑過 ≠ 上線驗過。
3. 這次改動新引入什麼風險？預設值安全嗎？失敗時會不會是安靜的？
4. 有沒有留下不一致？文件、註解、其他呼叫端、排程——改了 A 沒連動 B 的都算。
5. 誰在用這個東西？他們知道改了嗎？通知要寫「對方視角的用法變化」，給自己的待辦不能替代給對方的通知。

研究類任務（同一骨架）：
1. 答的是當初問的問題嗎？查得多 ≠ 答得對。
2. 每條結論標證據等級（官方文件／親手實測／推論／傳聞）；查詢有上限就標「前 N 筆，可能截斷」；禁止拿舊記憶當現況——「沒看到」只證明當時沒有。
3. 哪條結論錯了傷害最大？對它做反面查證，別只收集支持自己的證據。
4. 跟先前的結論或記錄矛盾嗎？明著指出並更新，不讓兩版真相並存。
5. 結論落地了嗎？要人決策的，收斂成編號選項，不是散文。

【② 還能怎麼優化】最多 2–3 條、具體可執行、標值不值得現在做；**沒有就寫「無」——禁止為了有產出而發明建議**。

規則：自檢在寫總結之前跑，不是寫完再補；混合任務兩組都掃、重疊的答一次。
